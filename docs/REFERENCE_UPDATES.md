## 2. 记录口径

每次有实际观察时，记录：

1. 来源 ID、观察日期、官方 URL、旧基线与新基线；HEAD、tag、发布提交、主线自报版本分别记录。
2. 实际读取文件/段落与差异摘要；未联网、读取失败、未覆盖内容必须明确说明。
3. 本地已有覆盖、适用场景、不应触发的反例和可能成本；新版本不自动意味着要采用。
4. 处理结论：待核实、已有覆盖、候选待审、择优采用、暂缓、拒绝。真正采用须链接已确认工作项与实际验证；登记不替代批准。
5. 实际落点、验证范围、未验证事项和局部回退方式。

“未核对”不是“无更新”；“已核对某段”不是“已跟进整个项目”；“研究候选”不是“已安装”。不设自动追平指标，不自动启用定时任务、下载、安装、知识回写或发布。

## 5. 日常维护方式

1. **发现待参考来源**：指新发现且尚未实际研究的外部项目或来源。在总表末尾单独新增一行，分配不复用的 ID，填来源、类别、参考方向与备注，状态为“待参考”，吸收内容及日期为“—”。来源身份不明就标待核实，不填猜测地址。已有项目的未研究内容不作为新来源登记。
2. **实际参考后**：补实际读取范围、固定版本和核对日期，按结果设为“已参考·待吸收”“已参考·依据引用”“暂缓”或“不采用”，不因读过就填已吸收。
3. **确认并实际吸收后**：在同一行追加该批次的具体内容、吸收日期及原采用记录链接，改为“已参考·部分吸收”；详细落点和验证仍由原工作项提供。
4. **再次吸收**：在同一来源行追加下一批，不覆盖旧内容/日期；在本台账追加批次详情，来源总表仍是唯一项目入口。
5. **只发现已有来源的上游更新或未研究内容**：更新原行的参考方向与备注及观察记录，不另算新来源、不改回“待参考”，不改变已有吸收日期。不以本分支登记或模板填写代替原有授权与验证。
