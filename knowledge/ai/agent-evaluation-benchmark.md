# Agent 评测与基准体系

> 原知识条目：Excellent（11964948@qq.com）。

### 目标
- 让 Agent 能力可量化、可回归、可持续优化。

### 适用范围
- 适用于研发阶段评测、发布门禁评估和线上质量回归。

### 评测维度
- 正确性：任务是否完成且结果正确。
- 稳定性：同类任务重复执行波动范围。
- 时效性：平均耗时与超时率。
- 成本：单任务 token 成本与工具调用成本。
- 安全性：是否触发策略违规或越权行为。

### 基准集构建
- 核心场景题集：覆盖高频业务任务。
- 边界场景题集：异常输入、缺失上下文、冲突约束。
- 红队场景题集：提示注入、数据泄露诱导、越权调用。

### 门禁规则
- 关键场景正确率不得低于既定阈值。
- 安全违规项必须为零才可发布。
- 成本与时延回退超阈值必须阻断发布。

### 执行清单
- 每次模型、提示词、工具变更都触发回归评测。
- 基准集按业务优先级分层维护并定期扩充。
- 评测报告必须包含质量、安全、时延、成本四维趋势。

### 验收标准
- 关键路径题集通过率达到阈值且稳定性达标。
- 安全红队场景无阻断级失败项。

### 常见失败模式
- 只看演示样例，不做标准化回归评测。
- 只看正确率，不跟踪安全与成本退化。

### 回滚策略
- 评测结果异常时，暂停发布；按已授权恢复方案评估回到上一个合格版本，不自动操作生产。
- 重新执行全量基准评测后再恢复放量。

### 方法与提示的真实行为评测（U10）

用用户任务、最少必要原始资料和允许的副作用范围构造案例，不向评估者提供标准答案或希望其发现的问题。观察实际回答、文件差异和工具行为，而非只检查标题、关键词或自报“遵守了规则”。不涉及模型产品的普通改动，不因此新增评测服务。

- 题集包含正常任务、边界和“不适用”反例；已证实失败补入原项目案例/测试，记录触发条件、原始证据和期望行为。
- 结果正确但越权读取凭据、误改无关文件或伪造确认，仍不满足任务。保留过程证据，但不要复制密钥或私人数据。
- 主观裁判先用已知对错案例核对判断尺度，特别检查“漏报真实缺陷”和“误阻断合法修改”；判断附理由，仍不取代用户确认和确定性检查。
- 去偏评估需要独立上下文；同一作者复核标为自检。按风险选择，不强制每轮新建团队或工作区。
- 有稳定性疑问时重复运行并记录所有结果、环境和变化，不挑最好一次，也不靠无限重试刷绿；次数和阈值来自本项目需要，不照搬通用 k 值。

案例维护采用有依据的局部修订，保留历史失效条件；不创建第二份计划、运行时记忆或自动更新用户全局记忆。来源及边界见 [UmaDev 吸纳映射](../../docs/UMADEV_SOFT_CONTENT_ADOPTION.md) U10。
