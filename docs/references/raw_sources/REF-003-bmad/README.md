## 2. 官方核心方法原文摘录

### 2.1 Forge Idea & 想法验证 (Explore and Validate an Idea)
> 来源文件：`plan/explore-and-validate-an-idea`
> “Before writing architecture or tasks, ruthlessly stress-test the core premise: What is the riskiest assumption? What is the counter-evidence? Can this idea be invalidated with a low-cost spike? If new information surfaces, update original requirement IDs rather than inventing unlinked sub-items.”

### 2.2 规划路径选择 (Choose a Planning Path)
> 来源文件：`plan/choose-a-planning-path`
> “Not all projects require heavy sequential rituals. Match the planning depth to the risk profile of the change. Keep role handoffs clean, and specify clear input/output contracts between phases.”
