# Plan: Windows 测试基础与用户目录隔离

## Context

Windows 测试曾因只设置 `HOME` 而写入真实用户目录。当前仓库还缺少完整用户级接入面摘要、安全复跑入口、重叠失败登记和 Windows 多版本证据。

## Architecture Impact

- 新增纯目录说明对象，默认行为保持不变；
- `SkillManager` 和 `IntegrationManager` 共享目录来源；
- 测试公共条件提供唯一临时用户目录；
- 测试支持层生成真实用户位置摘要和安全基线证据；
- GitHub Actions 增加独立 Windows 基线任务；
- 不修改九阶段真实控制、扩展平台或界面。

## Implementation Order

1. 先实现目录说明对象和纯解析测试；
2. 接入两个管理器并保持默认兼容；
3. 建立唯一临时用户目录条件；
4. 建立完整用户级接入面摘要和 Windows 路径同一性；
5. 只运行隔离自检；
6. 迁移并运行两个高风险测试文件；
7. 增加安全基线入口和失败登记；
8. 增加 Windows 3.10、3.11、3.12 持续检查；
9. 运行定向检查、完整基线和独立审查。

## Risks & Mitigations

- 风险：目录注入改变正常用户行为。缓解：参数可选，默认继续解析真实系统目录，并增加兼容测试。
- 风险：摘要短名单遗漏新宿主路径。缓解：从现有完整入口生成范围，并测试声明范围等于摘要范围。
- 风险：测试仍保留第二套 `fake_home`。缓解：公共条件成为唯一来源，高风险测试全部迁移。
- 风险：主目录外 `CODEX_HOME` 漏检。缓解：内部比较使用完整规范化绝对路径。
- 风险：基线任务绿色被误解为测试全绿。缓解：安全、测试、证据三个结果分开显示。
- 风险：高风险测试再次污染。缓解：隔离自检未通过前禁止运行完整文件。

## Rollout Strategy

- 所有能力先仅用于测试和持续检查；
- 高风险测试按“隔离自检 → 两个文件 → 定向范围 → 完整基线”逐层放开；
- Windows 基线先作为安全和证据任务，不冒充产品质量全绿；
- 不安装用户级 Skill，不合并，不推送；
- 回退时删除可选目录接入和测试工具，但不得恢复只设置 `HOME` 的做法。
