# Proposal: Super Dev 2.6 可靠性收敛

## 目标

把 2.5.1 已有的工作项身份、状态快照、阶段记录、当前代码版本摘要、验证结果和交付事实收敛成一条可信链路：

- `workflow-state.json` 是唯一真实流程状态；
- `SESSION_BRIEF.md` 只根据最新状态自动生成；
- `pipeline-state.json` 在旧项目升级时一次迁移，成功后删除，生产代码不再读写；
- 所有权威状态通过统一入口提交，具备修订冲突、锁、原子写、快照和恢复；
- 关键验证绑定工作项和当前代码版本，代码变化后旧结果失效；
- 正式发布成功后只更新 `released`，不推导部署或运营成功；
- 版本表面统一升级为 2.6.0。

## 动机

当前仓库已出现可复现漂移：相同变更已经发布为 v2.5.1，但会话状态仍显示“等待发布”；旧七阶段引擎另写 `pipeline-state.json`，会话简报也存在两个生产写入口；验证身份、扩展证据和交付事实使用不同结构。继续增加功能会放大这些问题。

## 范围

影响状态持久化、工作流引擎、专家阶段证据、会话恢复、验证身份、质量与发布证据、发布记录和版本一致性。

## 明确不做

不增加阶段，不提升影子账本控制权，不建设 Agent Runtime、多代理调度、多项目 Fleet、Memory 2.0、Engineering OS、通用插件市场、图形界面或供应链签名平台。
