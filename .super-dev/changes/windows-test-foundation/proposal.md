# Windows 测试基础与用户目录隔离提案

## Description

建立不会触碰真实用户文件的 Windows 测试基础：统一测试用户目录、自动覆盖完整宿主用户级接入面、固定历史与当前失败口径，并在 Windows Python 3.10、3.11、3.12 上取得可重复证据。

## 结论

在接入任何扩展能力前，先建立可重复的 Windows 测试基线，并彻底隔离测试与真实用户目录。阶段 0 只处理测试安全、失败分类和基线证据，不实现扩展平台，也不要求历史失败继续保持失败。

## 当前证据

- 历史 Windows 定向检查：187 项中 177 项通过、10 项失败；
- 历史较宽单元检查：2355 项通过、55 项失败、3 项跳过；
- 35 项用户目录相关失败属于上述 55 项的子集；
- 两个高风险测试文件曾在真实用户目录创建 49 个宿主接入文件；
- 当前测试多处只设置 `HOME`，而 Windows 上 `Path.home()` 和 `expanduser()` 优先使用 `USERPROFILE`；
- 当前 GitHub 持续检查只运行 Ubuntu 的 Python 3.10、3.11、3.12；本机 Python 3.13 只作为诊断环境。

## 改动范围

### 1. 统一用户目录来源

- 新增不含业务分支的用户目录说明对象；
- `SkillManager` 和 `IntegrationManager` 接受可选目录来源；
- 没有传入时保持当前真实用户目录行为；
- 测试必须显式传入唯一的临时用户目录。

### 2. 测试隔离和真实目录保护

- 公共测试条件统一设置 `HOME`、`USERPROFILE`、`HOMEDRIVE`、`HOMEPATH`、`CODEX_HOME` 和必要的 XDG 目录；
- 删除高风险测试中的第二套 `fake_home`；
- 真实保护范围从 `SkillManager` 三类路径表和 `IntegrationManager` 完整用户级入口生成；
- 覆盖用户级协议、命令、技能、智能体、兼容文件、可选用户文件和主目录外的自定义 `CODEX_HOME`；
- Windows 路径先解析真实位置，再统一盘符、分隔符和大小写，并用 `commonpath` 判断包含关系。

### 3. 安全基线入口和证据

- 使用 Python 实现跨平台安全入口，不依赖 Bash；
- 固定隔离自检、用户目录检查、Windows 定向检查、完整单元检查和重复性检查；
- 报告分别记录隔离安全、测试结果和证据完整性；
- 历史 10、55、35 与隔离后当前基线分开保存；
- 失败登记允许一个测试具有多个范围标签。

### 4. Windows 持续检查

- 在 `.github/workflows/ci.yml` 增加独立 Windows 基线任务；
- 实际运行 Python 3.10、3.11、3.12；
- 隔离失败、真实目录变化或证据缺失必须失败；
- 普通测试失败必须保留并明确显示，不能伪装为全部通过。

## 不在范围内

- 不实现扩展配置、扩展执行器、扩展证据平台或权限归属平台；
- 不清零阶段 1 的全部 Windows 产品失败；
- 不实现 UNC、保留文件名和 8.3 短文件名的完整产品写入守卫；
- 不接入测试先行、系统化调试、想法打磨、文档评审或外部知识；
- 不连接九阶段真实编排合同；
- 不合并、不推送、不修改用户级 Skill；
- 不新增图形界面。

## 验收

1. 高风险测试只写入唯一临时用户目录；
2. 完整宿主用户级接入面在测试前后没有变化；
3. 主目录外自定义 `CODEX_HOME` 被保护；
4. Windows 路径同一性规则覆盖大小写、盘符、分隔符、`..`、符号链接和目录连接；
5. 历史 `35 ⊆ 55`，历史 10 与 55 可部分重叠且禁止相加；
6. 隔离后当前基线不覆盖历史记录；
7. Windows Python 3.10、3.11、3.12 产生实际证据；
8. 运行前后工作区除预期证据外没有额外改动；
9. 默认产品行为与当前版本一致；
10. Ruff、定向测试、完整安全基线和独立审查满足任务表要求。

## 回退

可以删除安全入口、测试条件、证据文件和两个管理器的可选目录参数；默认目录解析保持原行为。不得回退成“Windows 测试只设置 `HOME`”。
