# 极限需求澄清与文档回写盘问法 (Grill with Docs)

> **核心哲学**：不要当一味顺从用户的“点头娃娃”。AI 与工程师必须像严苛的主考官一样，揪住模糊概念、暗含依赖与未定义状态连续追问，并在决断后立刻写回真源。

---

## 1. 盘问的三个聚焦点

1. **挑出模糊伪需求词汇**：
   - 看到“必要时同步”、“支持高并发”、“合理重试”、“优雅降级”等词汇时，必须停下并质问：
     - 具体超时时间是多少毫秒？
     - 超过几次重试算彻底失败？
     - 降级时的用户界面具体显示什么？
2. **强迫在互斥技术路径中二选一**：
   - 当发现两个需求互相矛盾（例如“既要强一致性实时更新，又要离线极速读取”）时，必须打断：
     - 请在方案 A 与方案 B 之间做出明确选择，本期不支持兼得。
3. **推演边缘极端场景 (Corner Cases)**：
   - 用户断网了怎么办？
   - 权限撤回但 Token 仍未过期怎么办？
   - 两个写操作在同一毫秒发生怎么办？

---

## 2. 闭环执行流程

```text
[识别模糊语义] ──> [发起盘问 (Grill)] ──> [用户抉择决断] ──> [原地写回原文档] ──> [争议场景回读验证]
```

- **最关键动作：原地写回**。盘问决不能停留在聊天气泡里，必须将达成的共识字字句句更新回 PRD 或架构设计文档中。

---

## 3. ⚡ Super Dev 流水线全自动注入路径 (Automatic Pipeline Injection)

本方法是 Super Dev 核心文档门禁（`DOC_CONFIRM_GATE`）的前置硬性审查逻辑，**默认全自动触发**：

- **触发阶段**：`docs`（文档冻结前）阶段。
- **生效角色**：`ARCHITECT`（架构师专家，见 `super_dev/experts/builtin/ARCHITECT.md`）与 `PLANNER`。
- **底层机制**：
  - 架构师产出 `output/*-architecture.md` 时，底层思考框架自动扫描模糊词汇（“高并发”、“优雅降级”等）并展开极端场景推演；
  - 遇到架构分歧或双轨冲突时，主动暂停并列出单选题，促成用户决断；
  - 决断结果在冻结前自动原地写回文档，严禁将决策留在聊天气泡中。

## 4. 💡 为什么必须在本项目吸纳，而不是让用户外部安装？

| 比较维度 | ❌ 用户自行安装外部 Skill / 插件 | ✅ 吸纳进 Super Dev 核心库 |
| :--- | :--- | :--- |
| **调用体验** | 必须由人工主动敲命令触发，容易因忘记而漏掉关键盘问 | **门禁卡扣**：作为冻结 PRD/架构前的强制自检环节，不盘问清边界不予放行 |
| **上下文干扰** | 外部 Grill Skill 包含大量与本项目无关的提问模板和提示词噪音 | **聚焦定制**：精准针对 Super Dev 的三份核心文档做架构与边界追问 |
| **文档一致性** | 外部工具盘问完后通常仅留在对话框，缺乏写回能力 | **闭环写回**：强制将裁决原地写回 `output/*-prd.md` 和 `architecture.md` |
| **负向决策留存** | 外部调用无法沉淀为团队规范 | **ADR 护航**：在 `ADR-REF-012` 中固化了“原地写回与反向盘问”的技术裁决 |
