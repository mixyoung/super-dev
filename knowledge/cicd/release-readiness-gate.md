# 发布就绪门禁清单

> 原知识条目：Excellent（11964948@qq.com）。

### 目标
- 用统一发布门禁阻断高风险变更，保证发布可控。

### 必过门禁
- 代码质量：lint、类型检查、静态分析通过。
- 测试质量：核心回归通过、阻断缺陷清零。
- 安全质量：高危漏洞清零，密钥泄露检查通过。
- 构建质量：制品可追溯、版本标签一致。
- 运维质量：发布与回滚脚本可执行。

### 发布前检查
- 是否完成变更影响评估与适用恢复预案。
- 需要灰度发布时，是否完成策略与阈值配置。
- 是否完成关键指标基线确认。

### 发布后检查
- 错误率、时延、成功率是否在阈值内。
- 告警是否异常增加。
- 关键业务链路是否连续成功。

### 恢复不是只把代码退回去（U14）

按交付形态检查安装、运行和恢复路径；离线工具不因本清单强制部署云服务。发布/回滚/关闭服务/修改数据都需要对应授权，知识建议本身不是授权。

执行恢复前核对目标制品、配置及数据兼容：新版本写出的数据能否被旧版本读取，迁移是否可逆，恢复会不会丢失之后的有效写入。回滚更危险时先说明依据并选择已授权的恢复方式，不能机械执行“回到旧版”。

演练优先使用合成数据和隔离环境。记录实际命令、目标版本、平台、退出结果，以及恢复后的关键业务与数据检查。脚本存在、命令返回零、只有健康端点响应，都不足以证明业务恢复；计划和演练不能冒充生产已恢复。清理仅限本轮创建且已核实归属的资源。

来源与适配边界见 [UmaDev 吸纳映射](../../docs/UMADEV_SOFT_CONTENT_ADOPTION.md) U14；不引入新评分或自动放行规则。

### 常见失败模式
- 只检查构建成功，不检查运行质量。
- 门禁定义存在但未强制执行。
