# Plan: Super Dev 2.6 可靠性收敛

## 1. 冻结合同

- 以已确认 PRD、架构和 UI/UX 约束为实现真源；
- 固定 `super-dev-2-6-reliability` 工作项、文档摘要和非目标；
- 前端与预览确认不适用，质量和交付仍必需。

## 2. 状态收敛

- 建立文件型状态存储服务、状态模型、修订号和冲突错误；
- 实现跨平台锁、原子提交、历史快照、审计追加和损坏恢复；
- 让 `review_state.save_workflow_state()` 成为兼容入口并委托统一服务；
- 会话简报改为唯一生成路径并写入来源工作项/状态修订。

## 3. 删除第二状态文件

- 将引擎阶段进度写入统一状态和阶段记录；
- 专家阶段检查改读统一状态与阶段记录；
- 旧 `pipeline-state.json` 一次迁移，留下摘要与迁移结果后删除；
- 删除生产代码及 Skill 中的旧读写引用。

## 4. 证据与发布事实

- 建立统一证据信封及候选匹配规则；
- 统一关键报告的工作项、当前代码版本和输入摘要语义；
- 代码变化后阻止复用旧 PASS；
- 正式发布成功后记录发布观察并更新 `released`，其他事实保持独立。

## 5. 版本与迁移

- 旧 Schema 保守读取和首次写入迁移；
- 统一 2.6.0 版本表面和发布说明；
- 不要求用户新增普通命令。

## 6. 验证

- 定向红灯、实现、受影响回归；
- 并发、崩溃、旧文件迁移、中文路径与 Windows 测试；
- Ruff、Black、Mypy、compileall、Skill 同步、贡献范围；
- Fresh Verification、Quality Gate、Release Readiness 与 Proof Pack 分开结算。

## 风险与缓解

- 多文件无法绝对事务：以 `workflow-state.json` 原子替换为提交点，其他摘要可重建；
- 迁移覆盖新状态：只迁移缺失且更旧的信息，保存原摘要和决定；
- 锁跨平台差异：独立实现并覆盖 Windows/Linux；
- 证据改造过宽：只接关键消费者，旧报告由适配器读取；
- 外部发布成功、本地记录失败：禁止重发，先只读核对再补记录。
