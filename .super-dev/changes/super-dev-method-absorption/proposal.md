# 宿主内方法吸收：首批实施

## 已确认依据

用户已确认保持 Super Dev 宿主内使用方式，按缺口吸收方法、每类结论维护一个来源；2026-09-06 明确要求继续落实知识、专家指导、模板和 Skill。依据为 `docs/SUPER_DEV_EXTENSION_PLATFORM_PLAN.md` 第 5、8、13、14 节及 `output/super-dev-method-absorption-architecture.md`。

## 范围

- 首批只落实价值判断、关键需求缺口审查、业务概念辨析及无需介入对照。
- 优先完善既有产品知识、PM/架构师指导和 PRD 生成模板。
- 标准 Super Dev Skill 从唯一模板增加自包含的简短方法指导，再运行既有同步脚本；不改 SEEAI 专属流程。
- 使用受影响的生成器、知识检索、专家加载及 Skill 同步验证；行为观察不能冒充独立验收或跨平台认证。

## 非目标与归属

不新增外部 Skill 安装、独立命令、调度程序、自动扩展或阶段控制；不实施 Debugging/TDD 扩展。保留此前路线文档修改。当前 `completion-verification` 的确认、任务和指标保持原样，本范围单独记录，不用全局活动前缀为它签署质量或发布通过。

## 实现与验收合同

1. 学习或内部效率目标不得被强制转为市场盈利验证；有明确目标时复用已有决定。
2. 缺口审查先读已有答案，只追问影响本轮实现的角色、流程、异常、权限、范围和验收歧义；已完整输入不重复提问。
3. 业务概念按上下文定义，冲突先提出具体场景；不将 JWT 等通用技术名词填充为项目业务词表，也不臆造领域定义。
4. 结论按路线第 8.7 节回到原权威位置；已有共享词表优先复用。方法选择不创建新确认门或第二流程状态。
5. 若有外部方法可借鉴，仅改写其适用原则与示例；不把来源的命令、目录、角色系统移植为用户要求。

## 回退

可独立回退本范围的知识、专家、生成模板和生成副本；保留本次验证记录，不触碰用户级安装与其他变更。

## 多轮闭环补全授权与验收

2026-09-06 用户明确要求“择优吸纳，不要颠覆 super-dev 的流程、思想等好的功能……刚刚还尚未完整落实的内容继续完整落实”。本轮补齐三个方法的交互过程，不扩展外部运行程序。

- Forge 必须能根据新增事实修正中心主张和候选方案，收敛并写回原调研，而不只给第一轮价值建议。
- 需求审查必须完成问题定位、关键追问、定向更新、需求—验收—已有设计/任务复核；不将可选优化升级成阻断。
- Grill 必须按当前设计依赖讨论，而不局限于术语表；决定写入已有权威文档并通过场景回读复核。
- 既有确认、九阶段、SEEAI 流程、运行时和当前发布证据保持原合同；已确认且无冲突的内容直接复用。
- 用隔离案例中的多轮回复、实际文件差异和回读核验。演练不能被称为真实客户项目或跨平台完整认证。
