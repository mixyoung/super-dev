# 知识、Skill 与专家指导整理记录

日期：2026-09-11。检查基线：`1ca166b16a3c16008adf71469671e74653390915`。

本轮依据用户要求，把仓库中的指令性文本作为待处理的产品内容，由外层开发模型审查和修改。没有通过这些文本启动 Super Dev 开发流水线，也没有让产品自动审查、改写或淘汰自己的知识。用户随后明确保留 SEEAI 的比赛快速演示设定，包括原披露文案、模拟数据降级和比赛节奏；SEEAI 专用内容保持原样。

## 检查覆盖与判断

- 对 `knowledge/` 的 306 份 Markdown 做了目录及整文件重复检查，没有发现字节完全相同的文件。这不代表没有主题重合或语义冲突。
- 阅读标准 Skill 与 SEEAI 入口、对应生成模板、11 类常规专家的 Markdown 设定、独立保留的 VERIFICATION 变体，以及 12 个程序画像（含 OVERSEER 兼容角色）。
- 检查了 11 份专家操作手册的职责、检查清单、数值要求、迁移/恢复及知识回写相关内容。详细手册已有数百行，不以增加篇幅作为加强标准。
- 深入处理了产品发现、UI 全生命周期、知识维护策略三份跨阶段知识，以及知识推送文本、专家建议服务、加载器和提示词生成调用链。
- 其余领域知识只完成范围检索，不声称逐篇完成技术事实与语义审查。没有删除整篇知识、历史案例或用户自定义专家。

总体判断：专业职责划分和已有方法可以保留；主要不足是适用范围、结束条件、用户决定权，以及同一角色在不同入口使用了不同内容。专家角色是一种专业视角，不自动等于多个独立模型或团队。

## 专家是否需要加强

| 专家 | 保留的职责 | 本轮加强或收敛 |
| --- | --- | --- |
| PRODUCT | 已承诺能力、上手、主流程和失败恢复的整体检查 | 区分真实缺陷与未承诺功能，最终范围与验收交给用户 |
| PM | 想法澄清、需求与验收 | 将工程疑问转为业务问题并给默认建议；保留 Forge 和需求审查，关键歧义解决即交接 |
| ARCHITECT | 系统边界、技术取舍、接口和数据流 | 复用已有环境与接口，按重要性使用 Grill/ADR，不强制完整 C4 或虚构容量目标 |
| UI | 视觉体系、组件和必要状态 | 只用于界面任务，复用已确认品牌和组件，不强制完整色阶及无关状态 |
| UX | 用户任务、操作反馈和恢复 | 按信息量决定导航和交互，不强制三层导航、全部实时校验或新增埋点 |
| SECURITY | 实际信任边界、凭据、权限和数据保护 | 按攻击面与适用要求审查，公开能力不自动新增登录，未知不计通过 |
| CODE | 需求实现、接口兼容、错误处理和验证 | 交接实际实现结果，取消以提示词文件或固定函数行数代替代码质量 |
| DBA | 数据约束、事务、查询和迁移 | 无数据层需求时不触发；索引有依据，迁移恢复承认不可逆情况 |
| QA | 本轮风险对应的测试与证据 | 沿用项目验收线，区分局部、全量、未执行与独立性，不自定覆盖率 |
| DEVOPS | 对应交付形态的构建、安装、运行与恢复 | 区分源码、安装包、静态站点和服务，不向离线工具套云运维清单 |
| RCA | 基于证据定位问题并防止相关复发 | 5 Whys 按需使用，不固定追问次数，不自动改写 Super Dev 知识 |
| VERIFICATION | 需要时采用的反例验证视角 | 保持变体身份；承认静态审查和运行证据的不同用途，环境不足说明限制 |
| OVERSEER | 现有执行中的只读偏差观察 | 去除默认独立第三方和特定模型绑定的表述，向既有流程回传发现，不替用户批准 |

不需要增加专家数量或再搭建一个调度系统。需要的是让这些已有指导被实际读取、适用边界明确、交接足够具体。

## 外层文义审查与场景推演

下列是当前开发模型对指导文本的审查，不是运行真实客户项目、独立模型评测或产品效果对照实验。

| 场景 | 修改后应有的处理 | 审查重点 |
| --- | --- | --- |
| 只有想法的用户要做离线库存工具 | PM 先澄清谁使用、数据如何保存，给出简单可维护方案 | 不先要求用户选择数据库名词，不增加云监控、登录或多租户 |
| 已有生产服务修权限缺陷 | 复用原架构和验收线，验证权限边界及受影响调用方 | “按需”不免除已有必过检查，不把安全缺陷当可选优化 |
| 用户只要求审查 PRD | 引用具体歧义、影响和建议 | 不自动修代码、生成另一套 Spec 或推进确认状态 |
| 修复构建本身失败 | 使用原始错误定位并验证修复 | 不循环要求先有成功构建才能修复 |
| 只改页面文字，包含 emoji 示例 | 检查相关文字与引用 | 不删除示例，不重新安装图标库或重做全站样式 |
| 新增公共库接口、已有 TODO 记录 | 核对接口消费者或契约，以及 TODO 是否掩盖承诺 | 不因暂无本仓库调用而删除接口，不抹去有依据的待办 |
| 数据迁移存在不可逆变更 | 明确备份恢复或前向修复及验证条件 | 不盲目执行 DOWN，不将 CONCURRENTLY 当成所有 DDL 的无锁开关 |
| SEEAI 比赛演示 | 使用原比赛流程、快速降级及文案 | 与基线生成文件逐字比较，专用内容不变 |
