# API 契约与版本治理指南

> 原知识条目：Excellent（11964948@qq.com）。

### 目标
- 保证前后端与外部调用方在接口演进中保持稳定兼容。

### 契约规范
- 请求参数：类型、必填、默认值、边界说明。
- 响应结构：成功与错误统一结构。
- 错误码：分层编码，具备可定位语义。
- 幂等性：关键写操作必须定义幂等策略。

### 版本策略
- 兼容更新：检查真实消费者对新增字段、枚举、默认值和严格解析的处理，不能一概认为新增即兼容。
- 非兼容更新：必须升主版本并提供迁移窗口。
- 废弃流程：公告期、灰度期、关闭期三阶段执行。

### 发布检查项
- 契约变更是否同步更新文档与示例。
- 是否补充契约测试与回归测试。
- 是否评估现有调用方影响范围。

### 消费者视角复核（U11）

沿用现有权威契约，包括经审查的代码生成契约，不强制切换到 OpenAPI、GraphQL、某种版本 URL 或新生成器。先对应真实消费者，再逐项比较方法/路径、输入约束、响应类型与空值、错误码与状态、权限和适用的重试/分页语义。

例如，路径不变但价格由数值变字符串、无权限由拒绝变空列表，仍可能改变业务行为；新增枚举会让穷举分支遗漏。用真实请求响应或现有契约测试验证，Mock 通过不等同真实集成通过。变更已确认语义时先按原确认合同更新权威文档，再对齐实现与消费者；不靠增加版本号本身证明兼容。

来源与不采纳项见 [UmaDev 吸纳映射](../../docs/UMADEV_SOFT_CONTENT_ADOPTION.md) U11。

### 常见失败模式
- 文档与真实返回结构不一致。
- 非兼容变更未升版本导致线上故障。
