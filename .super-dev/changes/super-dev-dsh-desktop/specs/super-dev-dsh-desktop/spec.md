## ADDED Requirements

### Requirement: DSH-01

SHALL 在现有宿主接入链中使用规范 ID `deepseek-harness`，仅将 `dsh` 归一化到它；显示 DeepSeek Harness（桌面版），保留现有宿主类别枚举。原生技能斜杠、模型自然语言选择与自定义命令文件是独立能力，不生成未经核实的 `.dsh/commands`。

#### Scenario 1: 正式入口和真实消费者
- GIVEN 项目与可注入用户目录，不读取现用 DSH profile 或凭据
- WHEN 用户选择 `deepseek-harness` 或 `dsh` 接入、查询、诊断或恢复
- THEN 同一规范 ID 经注册、目录、CLI、使用、恢复与报告链生效，安装位置为声明的 DSH 技能/规则面，不把 `deepseek` 视为新别名
- AND PATH 缺少 `dsh` 不被单独用作“桌面未安装”的结论

#### Scenario 2: 不混淆入口与厂商
- GIVEN DSH 使用非 DeepSeek 模型，且原生技能菜单注入标准或 SEEAI 技能
- WHEN 模型说明宿主、入口和阶段
- THEN 正确识别 DSH，不从宿主名称推断模型厂商，不否认本轮实际可用的原生斜杠入口

### Requirement: DSH-02

SHALL 从 `super_dev/skills/skill_template.py` 唯一模板渲染标准和 SEEAI 的 DSH 专属元数据与正文。元数据仅用固定 rc.5 已核实字段，保留共享知识权限、分层编排、语言、工作模式及确认合同；Claude/Codex 原渲染字节不得改变。

#### Scenario 1: 双技能与同期同步
- GIVEN 相同版本和模板输入
- WHEN 模板渲染、安装、刷新及仓库同步生成标准与 SEEAI 技能
- THEN 两种 DSH 内容均可由实际 rc.5 原生解析器读取，调用策略正确，副本与模板逐字节相等
- AND 不生成通用下划线调用策略键、Claude hooks、Codex 专属路径或模型配置

#### Scenario 2: 旧宿主不变
- GIVEN 修改前同版本的 Claude Code/Codex 标准和 SEEAI 渲染基线
- WHEN 加入 DSH 分流并同步
- THEN 四个旧渲染结果逐字节相同；宿主集合从 26 增到 27 是明确预期，保留精确数量及集合断言

### Requirement: DSH-03

SHALL 经实际装卸消费者验证幂等、归属和用户字节保护。采用已有安装清单，不另建 DSH 状态数据库。用户级能力仅在显式选择与注入目录下测试，默认不写真实用户目录。

#### Scenario 1: 幂等与原始字节恢复
- GIVEN 含 BOM、CRLF、首尾空白、用户文本和其他宿主块的合成项目文件
- WHEN 连续两次调用真实接入，再调用真实卸载
- THEN 重装不增加换行或重复块，卸载后原有用户与其他宿主字节保持不变，动态日志/时间戳另列
- AND 包含已复现的 `b"\n\nUSER_CONTENT\r\n\r\n"` 反例，不能删除或放宽它的断言

#### Scenario 2: 损坏、用户修改与部分失败
- GIVEN 用户改过的技能、开始/结束标记缺失或重叠、归属不明文件，以及可注入的中途写入失败
- WHEN 普通更新、卸载或同授权重跑
- THEN 不扩大覆盖/删除，不吞掉用户字节；保留项有明确原因，失败不伪造成功
- AND 重跑能修复本轮可归属的不完整安装，不破坏已成功的其他宿主

#### Scenario 3: 目录隔离
- GIVEN 注入的 home、DSH home 与现有旧构造调用
- WHEN 解析项目级/用户级技能目录并执行合成测试
- THEN 不借用 CODEX_HOME，不写真实 DSH home，旧构造调用保持兼容
- AND 真实模型测试不把复制父环境当成秘密隔离，不主动继承 API key 或 NODE_OPTIONS

### Requirement: DSH-04

SHALL 保留 `AGENTS.local.md` 的 DSH 限定短规则和旧宿主字节保护。在已批准的隔离原型中，将正常加载与异常确定拒绝分开验证：两个专属技能只能采用该项目经宿主解析、身份核对的 `.dsh` 定义；缺失、损坏、来源不适用或必要治理依据不完整时，在错误正文注入或受治理动作前拒绝。文本指导不冒充硬拦截，原规则预算失败不改写为通过，真实卸载不留 Super Dev 托管残余。

#### Scenario 1: 独立规则加载
- GIVEN rc.5 标准预设、项目根/子目录和共存规则文件，专属技能分别正常、缺失或损坏
- WHEN 原生规则加载器与桌面会话读取项目
- THEN 分别记录规则是否发现、是否进入预算和实际模型是否遵守，不以文件存在替代运行结果
- AND 接近预算或文件不可读时结果不被虚报为安全

#### Scenario 2: 真实卸载与共享回退
- GIVEN 正常装入的双技能及规则经过真实卸载，仅保留本来不属于本轮的共享技能
- WHEN DSH 分别通过原生选择和自然语言触发 Super Dev
- THEN 动态记录真实来源、工具、文件差异与阶段状态；无错误宿主执行、越门或扩权才可通过 A12
- AND 不以卸载后不存在的规则、永久残留、手改 Codex 或一次性守卫刷绿；不能保证则保持失败或受阻并阻断完整验收

#### Scenario 3: 原生来源与缓存复核
- GIVEN 0.2.2-rc.1 隔离副本、真实产品生成的双技能及共享 Codex 对照；其他普通技能也存在
- WHEN 经实际注册器、技能加载工具及原生斜杠注入路径选择标准或 SEEAI，或文件在目录发现后被移除、替换、损坏
- THEN 依据解析后的项目根、实际文件身份和当前调用策略核验，不相信正文自报来源；失败时拒绝，不回退共享/用户/自定义根中的同名定义
- AND 其他技能保持原有可用性；未知来源、缓存过期、压缩恢复与旧已加载历史均有拒绝或明确未验证结果，不能把只测新会话当全部通过

#### Scenario 4: 治理内容不足与真实卸载
- GIVEN 后置大规则使 DSH 块被省略，或双技能及短块经过真实卸载
- WHEN 原型拟注入正文或执行受治理动作
- THEN 宿主检查点确定拒绝并给出原因，受保护项目及 Core 状态不变；正常无预算压力的路径仍必须成功加载实际正文
- AND 不删用户规则、不改 Codex、不扩大默认规则预算，不保留影子技能、插件或永久标记；原型能力仅存在自有宿主副本，原始失败继续保留

### Requirement: DSH-05

SHALL 保持标准九阶段、文档确认及适用的预览确认；SEEAI、无 UI 沿用现有差异。持续目标、自动续跑、模型自报和评审结果均不是用户批准。

#### Scenario 1: 文档等待、拒绝和修订
- GIVEN 标准或 SEEAI 三文档已生成但未得到本任务明确批准
- WHEN 用户拒绝、要求修改、补充或目标驱动自动跟进
- THEN 不创建执行 Spec/代码，不自行记录确认；获准文档修订后重新绑定并等待
- AND 只有真实用户对当前绑定文档的明确确认才允许后续实施

#### Scenario 2: 适用预览确认
- GIVEN 标准模式 UI 样例已完成真实前端运行验证
- WHEN 预览尚未确认或用户要求修改
- THEN 保持预览/返工门，不提前做后端主实现；先改 UIUX 再返工并重新验证和等待
- AND 本次非 UI 宿主适配只按现有不适用路径实施，不免除该样例的预览门验收

#### Scenario 3: 目标 active/armed
- GIVEN 标准预设目标驱动已挂载，会话目标 active、续跑 armed 且代理实际进入空闲
- WHEN 自动发生后续轮次
- THEN 来源不明或自动生成的“继续”不被当成用户确认；记录实际轮次、受限产物和状态差异
- AND 如越过确认门则为阻断缺陷；隔离原型的确定拒绝、测试预算耗尽或暂停目标均不能冒充自然等待，现用预设不改

### Requirement: DSH-06

SHALL 对只读请求保持文件/阶段不变，从有效活动工作项恢复。在正常桌面工具集下复用已注入或加载的本轮技能；缺能力时报告限制，不反复加载来替代执行。

#### Scenario 1: 新建、增量和恢复
- GIVEN 新项目、已有项目及具有已确认/待确认活动任务的三个独立夹具
- WHEN 启动或说“继续当前流程”
- THEN 分别走 new、先基线的 evolve 或读取有效状态的 resume，不按时间戳选择旧任务，不重置已有确认

#### Scenario 2: 只读与自然停止
- GIVEN 只读解释/分析/审查输入、普通桌面工具集和技能加载记录
- WHEN 执行该输入或遇到缺工具
- THEN 只读请求不写项目文件/阶段；缺工具明确受阻，已加载技能不重复加载成循环
- AND 自然完成、用户等待、权限拒绝、预算停止和超时分别记录；测试守卫停止不算自然完成

#### Scenario 3: 无模型共享请求预算
- GIVEN 测试驱动设置可信运行标识及有限额度，所有分派均为无网络的合成适配器/传输计数器
- WHEN 正常调用、父子/辅助调用、并发、重试、取消或恢复尝试消耗额度
- THEN 在实际分派之前原子预留额度；额度 0 零分派，额度 1 两个并发最多一次分派，额度 2 不得分派第三次重试；父子及辅助调用共享累计值
- AND 未知运行标识默认拒绝，取消/重新排队不回收已用额度，同一测试重启不重置预算；跨进程或适配器内部路径未覆盖时明确受阻，不称全局预算完成

#### Scenario 4: 测试边界不替代正常执行环境
- GIVEN 文件、网络、进程、调度/目标及状态工具的执行边界尚待证明
- WHEN 原型机制检查通过或普通工具仍出现在目录中
- THEN 不据目录存在、路径字符串过滤或文件只读标签宣称任意 shell 已隔离；系统级读取/网络/进程边界缺失时不发送真实模型请求
- AND 不安装依赖、不读取现用认证，不用移除必要工具或替换真实执行结果证明正式桌面通过

#### Scenario 5: 当前不使用虚拟机与API按需询问
- GIVEN 用户确认修订三文档，但要求目前不使用虚拟机，并在需要模型API时再询问
- WHEN 继续同版原型准备、回归或判断是否可以进入真实模型测试
- THEN 仅执行项目内已授权的无模型工作，不创建或启动虚拟机，不借Docker/WSL绕过限制，不读取既有认证
- AND API、模型能力、数值预算与安全执行边界未明确前保持零真实请求；不因不使用虚拟机而降低原隔离和验收标准

### Requirement: DSH-07

SHALL 区分文件安装检查、静态能力核实和真实桌面行为证据。诊断、更新、恢复及运行报告覆盖新增宿主，但不通过把 ID 加入集合就宣称桌面已验证。

#### Scenario 1: 诚实的诊断与失败
- GIVEN 接入文件可生成，但桌面运行、网络或权限条件分别缺失
- WHEN doctor、能力报告或测试遇到这些条件
- THEN 文件/语法检查与桌面行为分别显示；缺条件报告受阻或失败，不伪造文件、通过或外部结果
- AND 不新增每次启动/恢复必跑的用户 doctor 门禁

#### Scenario 2: 当前证据与最小隐私
- GIVEN 本次当前代码版本、模板/技能哈希、DSH 版本和必要模型标识
- WHEN 保存运行证据
- THEN 绑定工作项、环境、输入、工具、差异、结束原因和实际耗时/请求数，保留失败尝试
- AND 不记录凭据、隐藏完整上下文、其他会话内容；未经授权不扫描连接或刷新认证

#### Scenario 3: 同版副本与历史证据隔离
- GIVEN 已绑定的冻结rc.3运行依赖、六个原生模块及其公开包元数据，另保留原混合版本副本
- WHEN 选择同版rc.3验证模式
- THEN 六模块基础源码与依赖版本一致，实际加载入口指向显式选择的同版目录，模块/原始包摘要及补丁均可核对
- AND 不因新结果重写旧回执，不把同版模块测试称为完整桌面构建或官方版验收；共享治理/预算实现的旧消费者继续回归

### Requirement: DSH-08

SHALL 保留已有质量阈值 90、宿主行为和权限边界；完成适用构建、lint/type-check/tests、同步及覆盖检查后才生成本地交付材料。十四项适用验收未满足不得声称完成适配。

#### Scenario 1: 回归与交付
- GIVEN 当前分支 `ocx/deepseek-harness-desktop-2026-11-05`、基线 `26b0cb6c98e723b8c12c4d721785a9cb91d6f761`
- WHEN 新实现经过原失败命令、受影响消费者和质量检查
- THEN 保留原断言与阈值，实际结果、未运行平台和阻断项可复查，不因报告生成成功称为通过
- AND 不自动提交、推送、开 PR、发布或修改真实用户级接入

#### Scenario 2: 沟通适配
- GIVEN 当时生效的语言规则和精确技术标识、产品文案分轨样例
- WHEN 真实桌面执行只读任务
- THEN 自然中文说明结论，状态为通过（PASS）/失败（FAIL）/受阻（BLOCKED），保留必要标识，不预支未批准语言候选效果
