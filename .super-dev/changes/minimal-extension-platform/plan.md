# Plan: 最小扩展平台

## Context

阶段 0 已完成 Windows 测试安全与用户目录隔离。阶段 1 在此基础上建设默认关闭的最小扩展内核，并迁移现有不安全的命令 Hook。

## Architecture Impact

- 新增独立 `super_dev/extensions` 模块，不创建第二套生命周期；
- 新增仓库级清单、来源锁、候选证据和扩展历史；
- 配置型命令 Hook 统一改走结构化执行器；
- 扩展默认关闭，主工作流状态不增加扩展写入面；
- 不新增图形界面或真实外部方法。

## Implementation Order

### 1. 数据合同

先实现扩展清单、来源锁、能力、所有权、候选身份、扩展事件和运行结果数据模型。所有枚举和必填字段在本阶段冻结，未知字段和未知枚举拒绝。

### 2. 来源与边界

实现稳定内容摘要、清单与来源锁一致性检查、所有权拒绝和可信能力求交集。内置适配器按仓库路径与内容摘要锁定；外部改编来源只定义合同，不启用执行。

### 3. 路径与证据

实现跨平台真实路径守卫，覆盖大小写、`..`、符号链接、目录连接、UNC 和不同盘符。候选身份覆盖基础提交、当前提交、未提交差异、暂存内容、未跟踪文件和工作区身份。运行证据由 Core 原子写入，历史追加保存。

### 4. 安全执行

实现结构化程序与参数列表执行器。默认 `shell=False`，固定工作目录，白名单环境，限长输出和敏感信息脱敏。Windows 使用 Job Object，POSIX 使用独立进程组。

### 5. Hook 迁移

配置型命令 Hook 改走结构化执行器；旧字符串命令返回阻断和迁移示例。可信 Python 回调与日志 Hook 保持兼容。YAML `type: python` 返回明确的不支持和迁移信息。

### 6. 合同探针与维护入口

增加一个只写扩展运行目录的内置合同探针。提供 `validate`、`inspect`、`verify-source`、`probe-contract` 和 `history` 维护入口。普通用户入口不增加新心智。

### 7. 配置与兼容

新增默认关闭的 `extensions` 项目配置。配置缺失等价于关闭；启用但允许列表为空仍不运行。除旧 Hook 安全迁移外，扩展关闭时保持当前 Core 行为。

## Verification

```text
数据模型与清单单元测试
→ 来源、所有权与路径负面测试
→ 候选与证据测试
→ 执行器和进程树测试
→ Hook 迁移测试
→ CLI/配置集成测试
→ 默认关闭等价性
→ Windows 相关回归
→ 完整单元检查
→ Ruff、类型和字节码检查
→ 独立只读审查
```

## Completion Criteria

只有全部任务和验收清单完成、真实用户目录变化为 0、进程树清理得到证明、扩展没有取得高风险权限、无真实外部方法接线时，阶段 1 才算完成。
